# 网易云点歌 → RVC 翻唱 → QQ 发语音：完整复用指南

> 源自 `E:\qq-bot` 项目，2026-10 实现并调优。
> 本文档可交给 AI 作为提示词，或作为人工部署手册。

## 一、这套系统能做什么

**一句话**：QQ 群友 @机器人 说「唱 晴天」→ 自动去网易云搜索 → 下载无损音频 → 人声分离 → RVC 换成目标音色 → 与原伴奏混音 → 发语音回群。

**实测性能**（RTX 3060）：
- 4 分钟歌曲：首次约 60~200 秒（含模型冷启动），后续约 40~60 秒
- 命中缓存：**0.4 秒**

**核心难点**（也是本方案的价值）：网易云对服务端有风控，直接调 API 会被拒。解法是**用可见浏览器持久化 profile 拿登录态**。

## 六、核心流程详解（`do_cover` 函数）

这是整个方案的技术核心，**六个步骤，每一步都有踩过的坑**：

```python
def do_cover(src_audio, model, f0up_key=0, index_rate=0.0,
             sep_model="HP2_all_vocals"):
    # 0. 加密格式解密（.ncm → .mp3）
    src_audio = _ensure_playable(src_audio)

    # 1. 统一转 44.1kHz 立体声 wav
    _ffmpeg_to_wav(src_audio, wav_in)

    # 1.5 源音频峰值归一化（缓解破音）★重要
    wav_in_norm, stats = _normalize_source(wav_in, jobdir)

    # 2. UVR5 人声分离
    for _ in uvr(sep_model, indir, vdir, [], idir, 10, "wav"): pass

    # 2.5 人声有效性检查（防止纯音乐版）★重要
    vocal_ratio = _vocal_energy_ratio(vocal_src, ins_src)
    if vocal_ratio < MIN_VOCAL_RATIO:      # 0.30
        raise RuntimeError("这首可能是纯音乐/钢琴版，没有人声可唱")

    # 3. RVC 音色转换
    vc.get_vc(model)
    _, wav_opt = vc.vc_single(
        0, vocal_src, f0up_key, None, "rmvpe", None, None,
        index_rate, 3, 0, 1.0, 0.33,
    )

    # 4. 混音输出
    _mix(conv_wav, ins_src, out_mp3, jobdir)
```

### 6.1 分离模型必须用 `HP2_all_vocals`，不能用 `HP5_only_main_vocal`

**这是踩过最深的一个坑。**

| 模型 | 行为 | 结果 |
|---|---|---|
| `HP5_only_main_vocal` | 只提取**主唱** | 和声、伴唱、合唱全部留在伴奏轨 → 听起来「还是原曲」 |
| `HP2_all_vocals` | 提取**全部人声** | 伴奏轨干净得多 |

**实测数据**（同一首歌《朋友的酒》）：

```
                       与原曲波形相关性   听感
HP5 + 固定混音            0.7585        很像原曲
HP2 + 固定混音            0.5422        仍有残留
HP2 + 自适应混音          0.2549        换声明显
```

### 6.2 自适应混音（不要用固定音量）

RVC 转换后的人声**比原始人声衰减 20~35%**，所以不能写死 `volume=1.0`，要根据实测响度反推：

```python
def _mix(vocal_wav, ins_wav, out_audio, workdir):
    rms_v = _measure_rms(vocal_wav)     # RVC 输出人声响度
    rms_i = _measure_rms(ins_wav)       # 伴奏响度
    TARGET_RATIO = 2.0                  # 目标：人声 RMS = 伴奏 x2 (+6dB)

    gain_v = min((rms_i * TARGET_RATIO) / rms_v, 6.0)
    gain_i = 0.55                       # 伴奏固定压低（压残留原唱）

    # 混音 → 峰值校准到 -1dBFS（线性，不压缩动态）→ 320k 输出
```

实测日志：`rms_v=0.1433 rms_i=0.2167 -> gain_v=3.02 gain_i=0.55`
（人声被放大 3 倍，才盖过伴奏里的残留原唱）

### 6.3 源音频归一化（防破音）

网易云搜不到原唱时会选中**翻唱版**，部分翻唱版 peak≈0.99 甚至超过 1.0（已削波）。这种音频经过分离 + RVC 后，高频失真会被放大 2~3 倍，听起来破音、发闷、金属感。

```python
NORMALIZE_TARGET = 0.89   # ≈ -1dBFS

def _normalize_source(src_audio, workdir):
    stats = _audio_stats(src_audio)
    if stats["peak"] <= 0.95:
        return src_audio, stats          # 正常就不用动，避免重编码损失
    # 否则整体压到 -1dBFS
```

> **注意**：已经削平的波形**无法真正修复**（信息已丢失），这里只是防止后续环节继续放大失真。

### 6.4 人声有效性检查

钢琴版、纯音乐版分离后「人声」几乎是静音，转换出来必然难听。加一道闸门：

```python
MIN_VOCAL_RATIO = 0.30   # 人声能量占 30% 以下就拒绝

vocal_ratio = _vocal_energy_ratio(vocal_src, ins_src)
if vocal_ratio < MIN_VOCAL_RATIO:
    raise RuntimeError("这首可能是纯音乐/钢琴版/伴奏版，没有人声可唱")
```

### 6.5 第 0 步：`.ncm` 解密（网易云加密格式）

如果你是从**网易云客户端下载**而不是走 API，拿到的会是加密的 `.ncm`，RVC 和 UVR5 都读不了。

`do_cover` 开头第一步就是解密：

```python
def _ensure_playable(src):
    """把 NCM(网易云加密) 等格式转成可读音频，返回可用路径"""
    if src.lower().endswith(".ncm"):
        out = ncmdump.dump(src)        # ← 解密
        return out
    return src
```

#### 用本包的独立实现（推荐）

`tools/ncmdump_standalone.py` 是**单文件、不依赖 pip 的 ncmdump 包**的版本，
改一下 `_ensure_playable` 即可：

```python
def _ensure_playable(src):
    if not src.lower().endswith(".ncm"):
        return src
    sys.path.insert(0, os.path.join(BASE_DIR, "tools"))
    import ncmdump_standalone as ncm
    info = ncm.decrypt_bytes(src)                  # 只解密拿 bytes
    out = src[:-4] + "." + info["format"]          # .flac / .mp3
    ncm.dump(src, out, skip_existing=False)        # 落盘 + 写封面标签
    os.remove(src)
    return out
```

或者命令行直接批量解（`.bat` 支持拖拽）：

```bat
Runtime\python.exe tools\ncmdump_standalone.py D:\CloudMusic -o D:\解好的 -d
```

#### ⚠️ 这个格式有一个必踩的坑：密钥流 off-by-one

`.ncm` 的音频流用 RC4 变体 XOR 加密。**密钥流必须从索引 1 开始，跳过第 0 字节**：

```python
block  = bytes(S[(S[i] + S[(i + S[i]) & 0xFF]) & 0xFF] for i in range(256))
stream = (block * (n // 256 + 1))[1 : 1 + n]   # ✅ 正确
#                             [:n]              ❌ 错，整首歌错位一字节，解出来是纯噪声
```

自己按 RFC 写 RC4 很容易漏掉这一点，然后用听感去 debug 会浪费很久——解出来是**噪声**而不是报错，很容易误判成"文件损坏"。

#### 关键参数（都不需要知道账号，格式固定）

| 项 | 值 |
|---|---|
| magic | `4354454e4644414d`（`CTENFDAM`） |
| 密钥区 XOR | `^ 0x64`，AES-128-ECB 密钥 `687A4852416D736F356B496E62617857`，解密后砍前 17 字节 |
| 元信息 XOR | `^ 0x63`，AES-128-ECB 密钥 `2331346C6A6B5F215C5D2630553C2728`，base64 + 砍前 22 字节 `163 key(Don't modify):` + 砍前 6 字节 `music:` |
| 音频流 | RC4 PRGA 密钥流，**drop 1 字节**后等长 XOR |
| 输出格式 | `flac`（无损）或 `mp3`（有损），由元信息里的 `format` 决定 |

#### mutagen 版本坑

官方 `ncmdump` 包在 **mutagen ≥ 1.46** 上处理 MP3 会直接崩：

```
AttributeError: 'ID3' object has no attribute 'RegisterTextKey'
```

因为 `ID3.RegisterTextKey` 已被删除。本包的独立实现改用标准帧显式构造（`TIT2`/`TPE1`/`TALB`/`COMM`/`APIC`），跨版本都能跑。

**`tools/ncmdump_standalone.py` 已做过逐字节验证**：合成 `.ncm` → 官方包 vs 本版各自解密 → FLAC/MP3 × 有/无封面 4 个用例，纯音频帧全部逐字节一致，ffmpeg 完整解码通过。详见 `tools/ncm解密-使用说明.md`。

## 八、QQ 插件要点（`astrbot_plugin_cover_sing`）

### 8.1 一条消息只能处理一次

`@bot 唱 xxx` 会**同时命中** `/唱` 指令和自然语言 handler（AstrBot 把 @bot 开头的消息当斜杠指令）。必须用 token 去重：

```python
def _claim_token(event):
    """原子性占位：同一条消息只允许第一个 handler 通过"""
    token = _dedup_key(event)
    with _dedup_lock:
        if token in _handled_tokens:
            return False
        _handled_tokens[token] = now
        return True
```

### 8.2 去重键**不能**用 `message_id`

实测：`event.send()` 发完语音后 `message_id` 会变，导致同一条消息被重新处理（重复翻唱两次）。

正确做法：

```python
def _dedup_key(event):
    # 群号 + 发送者 + 歌名 + 10 秒时间桶
    bucket = int(time.time() // 10)
    return f"{group_id}|{sender}|{keyword}|{bucket}"
```

**为什么要带群号**：同一个人在不同群点同一首歌，是两个独立请求，不能因为在 A 群刚唱过就把 B 群的拦掉。

### 8.3 歌名提取不能靠 AstrBot 的参数解析

AstrBot 的 `CommandFilter` **按空格切参数**，`唱 Let me go（温柔版）` 传进来只有 `Let`，后面的全丢。

必须自己从完整消息提取：
```python
def _extract_from_command(message_str, fallback=""):
    t = re.sub(r"\[At:\d+[^\]]*\]", "", message_str)   # 去 @ 组件
    t = re.sub(r"@\S+", "", t).strip()
    t = re.sub(r"^[/!！]", "", t).strip()             # 去唤醒前缀
    for kw in sorted(SING_KEYWORDS, key=len, reverse=True):
        idx = t.find(kw)
        if idx < 0: continue
        rest = t[idx + len(kw):].strip().lstrip(LEADING_NOISE).strip()
        if rest: return rest
    return fallback
```

### 8.4 永远校验返回的是不是真音频

```python
MIN_AUDIO_BYTES = 50000

def _looks_like_audio(body, content_type):
    if len(body) < MIN_AUDIO_BYTES: return False
    if "json" in (content_type or "").lower(): return False
    if body[:16].lstrip().startswith((b"{", b"[")): return False
    return True
```

## 九、歌曲选择逻辑（`_pick_song`）

不能「搜到什么就唱第一首」，要打分：

```python
def _pick_song(songs, keyword):
    kw = keyword.replace(" ", "").lower()
    best, best_score = None, 0        # 分数必须 > 0 才算命中

    for s in songs:
        name = (s["name"] or "").replace(" ", "").lower()
        artist = (s["artist"] or "").lower()
        score = 0
        if name == kw:                      score += 100
        elif kw in name:                    score += 60
        elif name in kw and len(name) >= 3: score += 40
        # 逐词匹配：只对长度 >= 2 的词计分，
        # 避免 "Let" 这种单单词把《Let It Go》错配进来
        for part in kw.split():
            if len(part) >= 2:
                if part in name:   score += 10
                if part in artist: score += 5
        if (s.get("duration") or 0) < 60000:
            score -= 30        # 太短可能是试听片段
        if score > best_score:
            best_score, best = score, s
    return best            # 对不上就返回 None，宁可不唱也不乱唱
```

**对不上时的行为**：返回 404「搜到相似歌曲但不是《X》，换个歌名试试」——比乱唱一首好得多。

## 十、翻唱结果缓存

同一首歌 + 同一音色，第二次直接复用，**省掉 30~60 秒**：

```python
CACHE_DIR = os.path.join(BASE_DIR, "cache")

def _cache_key(song_name, artist, model, f0up_key):
    raw_key = f"{song_name}|{artist}|{model}|{int(f0up_key)}"
    h = hashlib.md5(raw_key.encode("utf-8")).hexdigest()[:12]
    safe = "".join(c for c in f"{song_name}-{artist}" if c not in ILLEGAL_CHARS)[:40]
    return f"{safe}_{h}.mp3"
```

缓存键包含**音色和变调**，换了音色不会错误复用。

实测：199s（冷启动）→ 0.4s（缓存命中）

## 十一、踩坑清单（务必先读）

| # | 坑 | 解法 |
|---|---|---|
| 1 | **服务端扫码登录必被 8821 拒绝** | 用 Playwright 可见浏览器持久 profile，手动登录拿 cookie |
| 2 | **RVC 的 Config 会在导入时解析 sys.argv** | 脚本顶部先 `sys.argv = [sys.argv[0]]` |
| 3 | **cover_service.py 必须在 RVC_Core 目录下运行** | 脚本里 `os.chdir(RVC_ROOT)` + `sys.path.insert(0, RVC_ROOT)` |
| 4 | **UVR5 按目录扫描**，一个目录只能放一个文件 | 每次任务建独立子目录 |
| 5 | **ffmpeg 4.3.2 不支持 amix=normalize** | 用 volume + 手动峰值校准代替 |
| 6 | **message_id 发送后会变** | 用「群号+发送者+歌名+时间桶」做去重键 |
| 7 | **AstrBot CommandFilter 按空格切参数** | 自己从 event.message_str 完整提取 |
| 8 | **/sing 出错返回 200+JSON** | QQ 端会报 retcode=1200，必须返回非 200 |
| 9 | **HP5_only_main_vocal 只提主唱** | 用 HP2_all_vocals，否则听起来还是原曲 |
| 10 | **固定混音音量不够** | 用自适应：人声 RMS = 伴奏 ×2 |
| 11 | **翻唱版音源已削波** | 混音前先做峰值归一化到 -1dBFS |
| 12 | **纯音乐/钢琴版无法唱** | 加人声能量占比检查（<30% 拒绝） |
| 13 | **AstrBot 日志是 GBK 编码** | 启动带 PYTHONIOENCODING=utf-8，否则 emoji 日志会崩进程 |
| 14 | **改插件后必须重启 AstrBot** | 配置和代码都不热重载 |
| 15 | **ncmdump 需装在 RVC runtime 里** | 用本包 `tools/ncmdump_standalone.py`，免装 |
| 16 | **.ncm 密钥流必须 drop 第 1 字节** | 写成 `[1:1+n]`，写 `[:n]` 解出来是噪声且不报错 |
| 17 | **官方 ncmdump 在 mutagen≥1.46 崩 MP3** | `RegisterTextKey` 已删，改用显式 ID3 帧 |
| 18 | **bat 用 UTF-8 + chcp 65001 会乱码** | bat 存 GBK，且内部提示文字用纯 ASCII |

## 十二、给 AI 的复用提示词

如果要让 AI 帮你在这套基础上二次开发，直接把下面整段发给它：

```
我要做一个「QQ 群点歌自动翻唱」功能。请参考下面的架构和约束来实现：

【架构】
QQ群 → NapCat(OneBot v11) → AstrBot → 插件(识别点歌) → 本地FastAPI服务 → RVC

【本地服务必须实现】
POST /sing  (一条龙：网易云搜索→下载→人声分离→RVC转换→混音→返回mp3)
GET  /health, /models, /search, /login/status
POST /cover_path (本地文件翻唱), /speak (文字转语音)

【关键技术约束，违反会导致效果差或报错】
1. 网易云登录：服务端直接调API会被风控(8821)，必须用 Playwright 可见浏览器
   持久化 profile 手动登录，再导出 cookie 给服务端用
2. 人声分离必须用 HP2_all_vocals（不能用 HP5_only_main_vocal，
   后者只提主唱，和声留在伴奏里，听起来还是原曲）
3. 混音必须自适应：实测 RVC 输出人声比原人声衰减 20~35%，
   要按「人声RMS = 伴奏RMS × 2」反推增益，不能写死 volume
4. 混音前对源音频做峰值归一化到 -1dBFS（部分音源已削波，会放大成破音）
5. 加人声有效性检查：人声能量占比 <30% 的拒绝（纯音乐/钢琴版唱不了）
6. /sing 出错必须返回非200状态码+JSON，不能返回200+JSON
   （否则QQ端 ffmpeg 会报 retcode=1200 "Failed to open input"）
7. RVC 的 Config 会在导入时解析 sys.argv，脚本必须先清空 argv，
   且要 os.chdir 到 RVC_Core 目录

【插件侧约束】
8. @bot 唱 xxx 会同时触发 /唱 指令和自然语言handler，必须做 token 去重
9. 去重键不能用 message_id（send后它会变），要用
   「群号+发送者+歌名+10秒时间桶」
10. 歌名不能靠 AstrBot 的参数解析（它按空格切），要从完整 message_str 提取
11. 返回内容必须是真音频：校验 size >= 50000 且 Content-Type 不含 json

【音色模型】
用户自己提供 .pth 文件，放在 RVC_Core/assets/weights/
```

## 十三、最小验证清单

部署完按顺序验证，每步都应该通过：

```bash
# 1. RVC 服务起来了
curl http://127.0.0.1:8899/health
#    → {"ok":true,"models":[...]}

# 2. 网易云登录有效
curl http://127.0.0.1:8899/login/status
#    → {"logged_in":true}

# 3. 能搜到歌
curl "http://127.0.0.1:8899/search?kw=晴天"
#    → {"ok":true,"songs":[...]}

# 4. 完整一条龙（用 Python，避免中文乱码）
python -c "import requests;r=requests.post('http://127.0.0.1:8899/sing',data={'keyword':'晴天','model':'你的.pth','f0up_key':0},timeout=1800);open('out.mp3','wb').write(r.content);print(r.status_code,len(r.content))"
#    → 200 <大数字>

# 5. QQ 插件：群里 @bot 唱 晴天
#    → 先回「收到，正在找」，约 40~60 秒后发语音
```

**失败排查**：
- 第 2 步失败 → 重新跑 `netease_login_tool.py`
- 第 4 步返回 JSON 错误 → 看 error 内容（"没搜到" / "搜到相似但不是"）
- 第 5 步无反应 → 检查 AstrBot 白名单、插件是否加载、日志有无 retcode 1200
