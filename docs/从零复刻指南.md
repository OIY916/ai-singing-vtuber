# 从零复刻指南

目标：**一台什么都没装的 Windows 电脑**，照着本文一步步做完，能开出同样的直播。

全程约 1~2 小时，其中 RVC 整合包下载最花时间（几十 GB）。

每一步都有「✅ 验证」，不通过就别往下走。

## 1. 装 Python

1. 下载 **Python 3.10**（官方安装包，勾选 `Add python.exe to PATH`）
2. 安装后验证：

```powershell
python --version
# ✅ 输出 Python 3.10.x
```

> 为什么不打包虚拟环境：venv 里是绝对路径，换机器直接用会坏。用 `requirements.txt` 重建更可靠。

---

## 2. 装 RVC 整合包

翻唱服务的「变声引擎」是 RVC，它很大，必须单独下。

1. 获取 RVC 整合包（[RVC-WebUI](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI) 或任意第三方整合包，例如 RVCMAX）
2. 解压到**路径不含中文和空格**的地方，例如 `D:\RVC\RVCMAX`
3. 确认目录结构：

```
D:\RVC\RVCMAX\
├── RVC_Core\
│   ├── ffmpeg.exe                      ← 混音/解码用
│   ├── assets\
│   │   ├── weights\                    ← 你的 .pth 音色模型放这里
│   │   ├── uvr5_weights\
│   │   │   └── HP2_all_vocals.pth      ← 人声分离模型（必需）
│   │   └── rmvpe\
│   │       └── rmvpe.pt                ← 音高提取（必需）
│   └── infer\
└── Runtime\
    └── python.exe                      ← 跑翻唱服务的解释器
```

4. 把你的 **`.pth` 音色模型** 放进 `RVC_Core\assets\weights\`
   （本仓库不附带任何音色模型）

✅ **验证**：

```powershell
D:\RVC\RVCMAX\Runtime\python.exe -c "import torch; print('torch', torch.__version__, 'cuda', torch.cuda.is_available())"
# ✅ 能打印且 cuda True（有 NVIDIA 显卡时）
```

## 3. 装音频/直播软件

| 软件 | 作用 | 关键点 |
|---|---|---|
| **VB-Audio Virtual Cable** | 虚拟声卡，把程序声音变成「麦克风」 | 装完重启；设备管理器里应出现 `CABLE Input` / `CABLE Output` |
| **OBS Studio** | 抓皮套网页 + 输出虚拟摄像头 | 装完开一次，确认「虚拟摄像头」可用 |
| **抖音直播伴侣** | 推流到抖音 | 登录你的直播账号 |

✅ **验证**：

```powershell
Get-CimInstance Win32_SoundDevice | Select-Object Name
# ✅ 列表里能看到 VB-Audio Virtual Cable
```

---

## 4. 准备弹幕采集器

抖音弹幕需要第三方工具转成 WebSocket（本仓库不提供，因为它们的协议实现会变）。

1. 获取一个能输出 `ws://127.0.0.1:1088/ws` 的抖音弹幕采集器（例如 `douyinLive`）
2. 放到 `tools_raw\douyinLive\`（默认位置），或用 `paths.json` 的 `douyin_live_exe` 指到任意位置
3. 它需要一个 `config.yaml`，里面填你的直播间号、以及登录态 cookie（采集器自己扫码/填 cookie）

✅ **验证**：手动启动采集器，浏览器访问 `http://127.0.0.1:1088/` 能打开页面即算通。

## 6. 三份配置文件

### 6.1 复制模板

```powershell
copy stream\config.example.json                stream\config.json
copy cover_service\netease_cookie.example.json cover_service\netease_cookie.json
copy paths.example.json                        paths.json
```

### 6.2 `paths.json` —— 告诉程序东西在哪

```json
{
  "rvc_home": "D:/RVC/RVCMAX",
  "python": "",
  "music_dir": "D:/CloudMusic",
  "douyin_live_exe": ""
}
```

- `rvc_home`：**必填**，指向步骤 2 那个整合包根目录（其下应有 `RVC_Core\` 和 `Runtime\`）
- 其他留空即可，会自动推断

### 6.3 `stream/config.json` —— 直播间 + 大模型 + 音色

```json
{
  "room_id": "你的抖音直播间号",
  "llm_base": "https://api.openai.com/v1",
  "llm_key": "sk-你的key",
  "llm_model": "gpt-4o-mini",
  "sing_model": "",
  "tts_model": "",
  "cover_api": "http://127.0.0.1:8899",
  "douyin_ws": "ws://127.0.0.1:1088/ws"
}
```

- LLM 用**任意 OpenAI 兼容**服务即可，换厂商只改这三个字段
- `sing_model` / `tts_model` 留空 = 自动用 weights 目录里第一个音色
- 不配 LLM 也能开播（只是弹幕不会得到回复）

### 6.4 `cover_service/local_secrets.json` —— TTS 密钥

```json
{
  "tts_provider": "openai",
  "tts_base": "https://api.openai.com/v1",
  "tts_key": "sk-你的key",
  "tts_model": "tts-1",
  "tts_voice": "alloy"
}
```

用 MiMo 这类接口的话：

```json
{
  "tts_provider": "mimo",
  "mimo_key": "你的 MiMo key"
}
```

> 这两个 `local_secrets.json` 和 `paths.json` 都已在 `.gitignore` 里，不会被提交。

✅ **验证**：

```powershell
.\astrbot-venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'.'); import pathcfg; print(pathcfg.rvc_core())"
# ✅ 打印出 ...\RVC_Core 且路径真实存在
```

## 7. 登录音乐平台

```powershell
.\astrbot-venv\Scripts\python.exe cover_service\netease_login_tool.py
```

1. 会弹出**可见浏览器** → 手动登录（扫码或手机号）
2. 成功后 cookie 存到 `cover_service\netease_cookie.json`
3. 登录态保存在 `netease_profile\`，**下次不用再登**

> **为什么必须用可见浏览器**：服务端直接调接口会被风控拒绝（`8821 安全环境风险`），
> 只有真实浏览器登录拿到的 cookie 才可用。

✅ **验证**：文件存在且非空

```powershell
Get-Item cover_service\netease_cookie.json | Select-Object Length
```

### 附：下载到的 `.ncm` 怎么变成能用的音频

音乐平台客户端下载的是加密 `.ncm`，RVC / UVR5 都读不了。仓库里附了免安装工具：

1. 解压 `tools\ncm妙妙工具.zip`
2. 把 `.ncm` 文件拖到里面的 `解密ncm-拖到这里.bat` 上
3. 同目录会生成解密后的 mp3 / flac，直接能拿去翻唱

命令行方式：`python tools\ncmdump_standalone.py <音乐目录> -o <输出目录>`。

## 8. 启动与验证

### 8.1 启动（脚本会按顺序起三个服务）

```powershell
.\scripts\live\启动直播.ps1
```

输出应类似：

```
[1/3] 启动弹幕采集 (douyinLive :1088)…
[2/3] 启动 RVC 翻唱服务 (:8899)…（首次加载模型较慢，请耐心等）
[3/3] 启动直播主服务 (:8790)…

=== 服务状态 ===
  弹幕采集           :1088  ✅ 运行中
  RVC 翻唱         :8899  ✅ 运行中
  直播主服务          :8790  ✅ 运行中
```

首次启动 RVC 要加载模型，**可能要等 1 分钟**。

### 8.2 逐项验证

```powershell
# ① 三个端口
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 1088,8899,8790

# ② 翻唱服务（应返回 ok + 音色列表）
curl http://127.0.0.1:8899/health

# ③ 直播主服务（应返回 mode/队列等）
curl http://127.0.0.1:8790/api/state

# ④ 试唱一句（不唱歌，只验证 TTS→RVC 出声）
curl -o test.mp3 -F "text=测试一下" -F "model=" http://127.0.0.1:8899/speak
# ✅ test.mp3 有几百 KB，能正常播放
```

### 8.3 控制台

```powershell
.\scripts\live\直播控制台.bat
```

可以切歌、暂停、插队、暂停点歌、切换「唱歌时是否语音回复」、看队列和黑名单。

## 9. OBS / 直播伴侣 / 抖音

### OBS

1. 新建场景，添加 **浏览器源**：
   - URL：`http://127.0.0.1:8790/avatar`
   - 宽 1920 × 高 1080
2. （可选）再加一个浏览器源做字幕：`http://127.0.0.1:8790/overlay`
3. 右下角「启动虚拟摄像头」

### 直播伴侣

1. 添加「摄像头」→ 选 `OBS Virtual Camera`
2. 麦克风 → 选 `CABLE Output (VB-Audio Virtual Cable)`

### 抖音后台

开播设置里勾选「AI 生成」内容声明。

### 声音链路自检

```
翻唱服务 → 直播主服务混音器 → CABLE Input → (虚拟线) → CABLE Output
                                                          ↓
                                            直播伴侣的「麦克风」
```

✅ **验证**：在直播伴侣里看麦克风音量条，用控制台点一首歌，音量条应该跳动。

## 11. 故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 翻唱服务报「找不到 RVC_Core」 | `paths.json` 的 `rvc_home` 没填或填错 | 指向整合包根目录（其下有 `RVC_Core\`） |
| 翻唱服务报「没有任何音色模型」 | weights 目录空的 | 放 `.pth` 到 `<RVC>\RVC_Core\assets\weights\` |
| `/speak` 报「没有配置 TTS」 | 没配 TTS | 填 `local_secrets.json` 或设 `TTS_*` 环境变量 |
| 弹幕没反应 | 采集器没连上 | 检查 `douyin_ws` 端口、采集器是否登录、直播间是否已开播 |
| 弹幕有反应但没声音 | 音频路由不对 | 混音器应输出到 `CABLE Input`；直播伴侣麦克风选 `CABLE Output` |
| 页面白屏 / 皮套不动 | 缺皮套素材 | 确认 `avatar/front_cut.png` 和 `avatar/clips_out/*.webm` 存在 |
| 翻唱返回「服务忙」 | GPU 锁被占（上一首还在转） | 正常现象；等几秒，或看控制台队列 |
| 翻唱很慢（>2 分钟） | 显存不足 / 模型未预热 | 关掉其他占显存的程序；先手动 `/speak` 预热 |
| 登录态过期 | 音乐平台风控 | 重跑 `netease_login_tool.py` |
| 服务起不来但没有报错 | 端口被占 / 旧进程残留 | `.\scripts\live\启动直播.ps1 -Status` 查占用，`-Stop` 后重起 |
